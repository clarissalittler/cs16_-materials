One detail that's easy to miss but very important: look at the declaration char hello[20]. We had to make the destination array bigger than the text we initially put in it, because concat writes the second string into the same box the first string lives in. If we'd declared char hello[] "Hello" the compiler would have made a box exactly six characters wide (five letters plus the '\0'=), and copying ", World!" onto the end would have written right past the end of the array --- exactly the out-of-bounds sin we just spent a whole section warning you about. The destination needs spare capacity for everything you plan to append. C++ will not check this for you.

Now, note that this means we modified the first string to do this concatenation. That's very different than how the + operator worked on the string type, which didn't change the arguments passed into it.

This is an example of what's called a "destructive" operation, because it doesn't leave operands passed into it unscathed! This isn't inherently bad, you just have to be careful with it!

There are a lot more operations on C-style character array strings than we'll cover here. We'll revisit them in CS161B, but it's still worth seeing how they work at least once in CS161A.
